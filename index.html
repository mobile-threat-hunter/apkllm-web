Checks

    Entries (every entry libziparchive enumerates — failing gates are highlighted, never hidden)

    Decompression plan (four-reader model — which device reader consumes each entry, and how)

    Bytes are materialized only by the entry's own mapped reader: method 8 → libziparchive inflate, 0 → stored copy; a forged method ∉ {0,8} is read raw only by the lenient AssetManager (manifest / resources), while the strict readers — ART.DexFileLoader, NativeLibraryHelper, generic libziparchive — reject it, so there is no faithful extraction and the entry is reported, not re-read with another reader's algorithm. The manifest inputs on the Install gate tab drive the plan.
